## Abstract

This paper presents SentAI, an open-source MicroPython environment for high-level autonomous flight control on a minimalist embedded AI board that integrates an EdgeTPU accelerator and extends it with two 5 Mpx cameras and an onboard IMU. The platform is designed as a compact sensing and decision layer for micro-aerial vehicles, combining scriptable mission logic, dynamic TensorFlow Lite model loading, continuous onboard inference, and real-time communication in a resource-constrained MCU system. Architecturally, the board is conceived to go beyond a single fixed sensor viewpoint: the two cameras can be mounted in parallel or perpendicular configurations, enabling either stereo-like directional redundancy or complementary views such as forward-looking navigation and downward-looking scene understanding.

A second major contribution of the work is a careful systems-level analysis of the complete real-time visual path, from photons captured by the image sensor to buffers in MCU RAM and further to the EdgeTPU input memory. The implementation studies and optimizes each stage of this chain, including sensor acquisition, DMA-backed frame delivery, hardware scaling and pixel conversion, tensor preparation, and inference scheduling inside the real-time operating system. To sustain high frame rates, these operations are organized as a pipelined parallel workflow, in which camera capture and image preparation execute concurrently with TPU inference through dedicated RTOS tasks and a double-buffered staging design. This transforms the platform from a proof-of-concept integration into an industrialized embedded vision stack, showing how techniques that are straightforward in theory require careful orchestration in practice once memory locality, transfer latency, buffer ownership, and accelerator access become hard hardware constraints.

The flight-control concept explicitly targets two complementary UAV platforms. The first is Bitcraze Crazyflie, chosen as an agile indoor research vehicle that is easy to instrument, safe to iterate on, and well suited for rapid experimental validation. The second is a professional PX4-based autopilot stack accessed through the MAVLink standard, representing the path toward more robust outdoor and field-deployable operation. SentAI exposes a common high-level control layer from MicroPython for both targets, allowing mission scripts to issue flight actions, consume telemetry, and couple perception outputs with guidance decisions while preserving a uniform developer workflow across the lightweight indoor platform and the professional-grade MAVLink ecosystem.

At the perception level, the main contribution is a dual-camera, multi-model runtime tailored for sensor-rich drone operation. The source code integrates camera initialization across both sensors, explicit runtime camera switching, per-camera geometric configuration, image rotation support, and a frame-sequencing mechanism that guarantees clean acquisition after a sensor change by waiting for fresh post-switch frames. This camera-switching concept is essential for aerial robotics because it allows the system to alternate between viewpoints according to mission phase: one camera can support obstacle awareness or pilot-centric navigation, while the other can support nadir inspection, target localization, or tracking relative to the ground plane. Over this visual substrate, SentAI adds continuous EdgeTPU detection, lightweight multi-object tracking, IMU-aware motion compensation, ground-plane projection, GPS-referenced localization, and dynamic model switching so that different neural networks can be invoked according to context, target type, or flight mode.

This optimization effort is especially important for YOLO-class detectors, whose input dimensions place strong pressure on the memory budget of an MCU-based platform. The work therefore addresses the practical problem of memory rearrangement and allocation across internal RAM and external SDRAM so that large model inputs, staging buffers, tracking structures, and MicroPython runtime data can coexist while minimizing unnecessary copies and other inefficient operations. The camera subsystem is directly coupled to the processor through a high-bandwidth embedded capture path, while the runtime adds a dedicated hardware-assisted stage for image conversion, resizing, and tensor preparation before inference. In this sense, the paper is not only about deploying models on embedded hardware, but about demonstrating how to make such deployments reliable, repeatable, and efficient under real hardware limits.

In addition to the embedded runtime, the work also provides a custom YOLO model trained on an open synthetic image dataset created specifically for drone-navigation scenarios in inhabited spaces. The dataset is designed as a reusable starting point for the community and contains aerial views captured both at nadir and at approximately 45 degrees, so that models can learn to generalize across the two most relevant operational perspectives for low-altitude UAV missions. This contribution is intended as a pre-training and adaptation basis for applications that must implement strict navigation and avoidance rules in populated environments, including use cases aligned with European drone operation constraints such as the A0-A3 and A2 categories. By combining an open embedded runtime, an open dataset, and a transferable detection model, the proposed framework aims to reduce the entry barrier for developing regulation-aware autonomous drone systems that couple onboard perception with high-level flight policies.

The result is an open-source embedded autonomy stack in which MicroPython orchestrates high-level drone behavior, high-fidelity sensors provide the situational context, and multi-model AI pipelines adapt the onboard perception strategy to the needs of the mission.
