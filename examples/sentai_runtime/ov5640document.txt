1. DOCUMENT PURPOSE
======================================================================
This file summarizes the hardware integration, power sequencing, host interface behavior,
SCCB/I2C considerations, timing/layout recommendations, debug checklist, and autofocus
firmware command interface for the OV5640 camera module.

It is intended to help an automated agent or engineer quickly understand:
- electrical/power requirements
- host interface options
- power-down and power-off behavior
- SCCB addressing and debug procedures
- timing/layout constraints
- autofocus firmware command protocol and zone configuration

======================================================================
2. HIGH-LEVEL OVERVIEW
======================================================================
OV5640 provides:
- 10-bit video port D[9:0]
- 8-bit output modes using D[9:2]
- SCCB control interface (I2C-like)
- PWDN pin (active high)
- RESET# / RESETB pin (active low)
- XCLK input and PCLK output
- optional embedded autofocus firmware for VCM AF modules

Two power saving modes are described:
- Power Down mode:
  - camera supplies remain powered
  - sensor enters standby by driving PWDN high
  - only supported for power-saving when DOVDD = 1.8V and DVDD is generated internally
- Power Off mode:
  - camera supplies are cut
  - used when higher IO voltage or external DVDD makes power-down unsuitable

======================================================================
3. REFERENCE POWER / SUPPLY GUIDELINES
======================================================================
Recommended sensor rails:
- AVDD:
  - analog supply
  - clean supply
  - 2.6V to 3.0V
  - 2.8V recommended
  - for OTP write: AVDD must be 2.5V ± 5%
- DVDD:
  - digital core supply
  - 1.5V ± 5%
  - internal regulator use is strongly recommended when applicable
- DOVDD:
  - digital IO supply
  - 1.7V to 3.0V
  - 1.8V recommended

Grounding/layout:
- AGND and DGND should be separated inside the sensor/module
- connect AGND and DGND together at a single point outside the module / very close to module connector
- do not connect them together inside the module PCB
- capacitors should be placed close to related sensor pins

Output bus width:
- D[9:0] = 10-bit RGB RAW output
- D[9:2] = 8-bit YUV / RGB output

Recommended power supply arrangements:

A) 2 external supplies
- DOVDD = 1.8V
- DVDD generated by internal regulator
- AVDD = 2.8V
- supports both Power Down and Power Off for power saving

B) 3 external supplies
- DOVDD = 2.8V
- DVDD = 1.5V external
- AVDD = 2.8V
- use Power Off mode for power saving
- Power Down mode is not supported for power saving in this configuration

======================================================================
4. HOST INTERFACE OPTIONS
======================================================================

4.1 Host 1.8V IO and OV5640 1.8V IO
- simplest case
- host supports 1.8V IO directly

4.2 Host 2.8V IO and OV5640 1.8V IO
Use 1.8V on OV5640 side and add level shifting between OV5640 and host for video signals.

Recommendations:
- add level shifters for:
  - HREF / HSYNC
  - VSYNC
  - DATA0~9
  - PCLK
- OV5640 output pins can become tri-state in standby (PWDN high):
  - HREF/HSYNC, VSYNC, DATA0~9, PCLK, FREX, STROBE, GPIO1~2
  - if tri-state is a problem, use ~10k pulldown resistors on those signals
- SCL/SDA tolerate high voltage:
  - OV5640 can use 1.8V IO while I2C pull-ups go to 2.8V
- PWDN and XCLK can accept 2.8V signals directly
  - direct 2.8V on PWDN is acceptable for power down
  - if spare level shifter channels exist, they may also be level shifted
- RESETB caution:
  - do NOT drive RESETB directly with 2.8V when OV5640 IO is 1.8V
  - reason: OV5640 has internal pull-up to IO power, causing leakage from 2.8V into 1.8V rail
  - solutions:
    1. host drives RESETB low only for reset, then leaves it floating/input during operation so internal pull-up drives it high to 1.8V
    2. add level shifter on RESETB

4.3 Host 2.8V IO and OV5640 2.8V IO
- OV5640 also supports 2.8V IO
- if DOVDD = 2.8V, then DVDD 1.5V must be supplied externally
- Power Off mode is recommended for power saving
- Power Down mode is not supported for power saving in this mode

======================================================================
5. CAMERA INTERFACE / PIN BEHAVIOR
======================================================================
Video interface:
- 10-bit port D[9:0]
- use D[9:0] for 10-bit RGB raw
- use D[9:2] for:
  - 8-bit YCbCr
  - 8-bit RGB raw
  - 8-bit RGB565

Sync behavior:
- HREF and HSYNC share the same pin: Href
- behavior/function of this pin is selectable through SCCB settings

Control pins:
- RESET# / RESETB:
  - active low
  - has internal pull-up resistor
  - should be controlled by backend chip for proper power-up sequence
- PWDN:
  - active high
  - has internal pull-down resistor
  - should be controlled by backend chip for proper power-up sequence

SCCB pull-ups:
- SIO_C and SIO_D should have external pull-up resistors
- typical value noted in docs:
  - 5.1k in interface section
  - around 4.7k in debug checklist
- practical interpretation: use roughly 4.7k to 5.1k pull-ups

======================================================================
6. POWER SAVING MODES
======================================================================

6.1 Power Down mode
Definition:
- all camera power rails stay on
- camera enters power-down/standby via PWDN high

Power-down can be used for power saving ONLY IF:
- DOVDD = 1.8V
- DVDD generated by internal regulator

If DOVDD > 1.8V:
- power-down cannot be used for power saving
- it may still be used for SCCB bus sharing or sharing a single DVP port with another camera

6.2 Power Off mode
Definition:
- all camera supplies are cut during save mode

Use power-off mode when:
- DOVDD > 1.8V
- external DVDD is required
- otherwise internal regulator drop may be too large and may cause overheating

======================================================================
7. POWER-UP / POWER-DOWN SEQUENCES
======================================================================

7.1 Power Down Mode - Battery On / Init sequence
Conditions:
- DOVDD = 1.8V
- DVDD via internal regulator

Timing:
- t0 >= 0 ms : DOVDD stable to AVDD stable
- t2 >= 5 ms : AVDD stable to sensor power-up stable
- t3 >= 1 ms : sensor power-up stable to RESET# high
- t4 >= 20 ms: RESET# high to SCCB initialization

Sequence:
1. Apply RESET# to OV5640 camera module (held in reset)
2. Pull PWDN high
3. Apply DOVDD and AVDD
   - may be simultaneous
   - if separate: DOVDD first, AVDD last
4. After AVDD has been stable for 5 ms, pull PWDN low
5. After 1 ms, pull RESET# high
6. After 20 ms, perform SCCB initialization
7. Then pull PWDN high to enter power-down mode
8. Pull XCLK low

Important note:
- after battery on, OV5640 should be initialized first, then set into power-down mode

7.2 Wake-up from Power Down
1. Apply XCLK
2. After 10 ms, pull PWDN low
3. Optional: run full SCCB initialization again

7.3 Enter Power Down
1. Pull PWDN high
2. Pull XCLK low

7.4 Power Off Mode - Camera On
Use when DOVDD > 1.8V and DVDD is external.

Timing:
- t0 >= 0 ms : DOVDD stable to AVDD stable
- t1 >= 0 ms : AVDD stable to DVDD stable
- t2 >= 5 ms : DVDD stable to sensor power-up stable
- t3 >= 1 ms : sensor power-up stable to RESET# high
- t4 >= 20 ms: RESET# high to SCCB initialization

Sequence:
1. Apply RESET# to module
2. Apply DOVDD, DVDD, and AVDD
   - may be simultaneous
   - if separate: DOVDD first, AVDD second, DVDD last
3. After 5 ms from last power stable, pull PWDN low
4. After 1 ms, pull RESET# high
5. After 20 ms, run SCCB initialization

Note:
- if module has no PWDN pin exposed, that means PWDN is tied to GND

7.5 Power Off Mode - Camera Off
1. Pull XCLK low
2. Turn off AVDD, DVDD, DOVDD
   - may be simultaneous
   - if separate: DVDD off first, AVDD second, DOVDD third
3. Pull PWDN low and RESET low

8. SCCB / I2C SHARING AND ADDRESSING
======================================================================

SCCB sharing:
- OV5640 SCCB bus can be shared with other I2C devices
- when OV5640 is active, access separation occurs by device address
- OV5640 device address:
  - write: 0x78
  - read : 0x79
- I2C accesses to other addresses do not affect OV5640 registers

If another device conflicts with OV5640 address:
- place OV5640 in power-down or power-off mode before accessing the other device
- in power-down/off, OV5640 leaves the SCCB bus free

Debug-related SCCB address families listed in notes:
- CIF sensors: 0xC0 / 0xC1
- VGA sensors: 0x42 / 0x43
- 1.3M and 2.0M sensors: 0x60 / 0x61
- 3.0M and 5.0M sensors: 0x78 / 0x79

SCCB debug tips:
- use pull-ups (~4.7k recommended)
- start with SCCB speed <= 100k for early debugging
- later increase up to 400k
- verify reads by reading registers 0x0A and 0x0B (version)
- verify writes by writing register 0x11 and observing PCLK frequency
- use oscilloscope capture of full SCCB init waveform to validate communication
- after SCCB soft reset, wait at least 2 to 5 ms

9. TIMING / PCB LAYOUT CONSIDERATIONS
======================================================================
OV5640 uses:
- XCLK as main input clock
- PCLK as output pixel clock

Recommendation:
- use PCLK as sample clock for video data

Key warning:
- if backend sampling timing relative to data is wrong, symptoms can include:
  - wrong color
  - fixed horizontal lines
  - moving horizontal lines

Delay model:
- Delay_XCLK = 0
- Delay_PCLK = PCB_Delay_XCLK + Internal_Delay + PLL_Delay + PCB_Delay_PCLK
- Delay_Data = PCB_Delay_XCLK + Internal_Delay + PLL_Delay + PCLK_to_Data_Delay + PCB_Delay_Data

9.1 If sampling with PCLK
clock_data_delay = Delay_Data - Delay_PCLK
                 = PCLK_to_Data_Delay + PCB_Delay_Data - PCB_Delay_PCLK

Implication:
- if PCB lengths of PCLK and Data are matched, then:
  PCB_Delay_Data = PCB_Delay_PCLK
  => clock_data_delay depends mainly on PCLK_to_Data_Delay
- therefore PCLK-based sampling is less sensitive to XCLK PCB delay

9.2 If sampling with XCLK
clock_data_delay = Delay_Data - Delay_XCLK
                 = PCB_Delay_XCLK + Internal_Delay + PLL_Delay + PCLK_to_Data_Delay + PCB_Delay_Data

Implication:
- much larger delay
- strongly dependent on PCB layout
- much more likely to create timing issues

9.3 EMI / ESD recommendations
- use PCLK as sample clock whenever possible
- XCLK and PCLK should not share EMI/ESD devices with other signals
- prefer dedicated ESD/EMI devices or separate R/C filters for XCLK and PCLK
- for dual camera designs, use a single ESD/EMI device or single R/C filter for XCLK and PCLK to minimize delay
- keep XCLK trace as short as possible
- keep PCLK trace length matched to data lines
- minimize FPC cable length

10. HARDWARE DEBUG CHECKLIST
======================================================================

10.1 Validate hardware design
- verify camera module function using a USB 2.0 test board / interface board if available
- module should display image correctly on PC
- check schematic and pin definitions
- verify AGND/DGND separation in module

10.2 Validate phone/host interface
- pin mapping matches module
- AVDD supplied by separate regulator
- DVDD and DOVDD may be separate or shared with other circuits if within spec
- if long flex cable is used, do not share module ground with noisy circuits
- on flip-phone type designs, sharing camera ground with LCD module can cause strong noise

10.3 Evidence module is working
Look for:
- PCLK output
- HREF / VSYNC outputs
- D[9:0] activity

Checks:
a) power voltages are within spec
b) input clock is correct
c) input signals are correct:
   - PWDN inactive
   - RESET inactive
   - SIO_D high
   - SIO_C high
d) for OV5640 and later, verify SCCB init waveform and completion

10.4 Camera interface checks
- verify polarity of HREF/HSYNC, VSYNC, PCLK
- ensure polarity matches backend/baseband expectations
- verify sample clock strategy
- if backend samples with MCLK/XCLK, do not enable unsuitable internal clock division and watch for timing issues
- verify window position behavior:
  - if interface uses HREF, window position is defined by sensor
  - if interface uses HSYNC, window position is defined by backend/baseband

10.5 Typical issue categories listed in notes
- line width too big
- insufficient output lines
- line width too small
- wrong window position
- horizontal sync issue
- vertical sync issue
- sample rate too high
- sample rate too low
- timing issue

11. IMAGE ORIENTATION / COLOR CHECKS
======================================================================

11.1 Image direction
Case A: Sensor 4:3, LCD 3:4
- full screen display is not full view angle
- full view angle display is not full screen

Case B: Sensor 3:4, LCD 3:4
- sensor rotates 90 degrees in module
- phone should change picture scan line direction
- can achieve full-screen and full-view-angle display

11.2 Color / brightness checks
Possible symptoms and causes:
- only red/green colors visible:
  - Y and U/V exchanged
- R/B exchange:
  - red/blue ordering issue
- color/brightness not continuous:
  - check D[9:0] connections
- image not centered on LCD:
  - output window likely incorrect

12. EMBEDDED AUTOFOCUS FIRMWARE OVERVIEW
======================================================================
This section applies to the OV5640 embedded firmware user guide for VCM AF modules.

Embedded resources/features:
- embedded micro-controller
- 4KB embedded program memory
- embedded VCM controller
- built-in AFC (Auto Focus Control)
- AFC collects edge information for programmable zones

There are two autofocus approaches:
1. Embedded auto focus solution
   - autofocus controlled by OV5640 built-in micro-controller
   - behaves more like a fixed-focus module from host perspective
   - faster because AF info and calculations are internal and real-time
2. External auto focus solution
   - AF logic runs in baseband/application processor
   - processor reads AF information over SCCB
   - processor computes focus and controls actuator over I2C
   - advantage: custom algorithms
   - disadvantage: slower than embedded AF

The firmware guide focuses on embedded autofocus.

13. AF FIRMWARE INTERFACE REGISTERS
======================================================================
Eight registers are used by the firmware interface:

- CMD_MAIN  = 0x3022
  - main command
  - write
- CMD_ACK   = 0x3023
  - command acknowledgment
  - read/write
- CMD_PARA0 = 0x3024
- CMD_PARA1 = 0x3025
- CMD_PARA2 = 0x3026
- CMD_PARA3 = 0x3027
- CMD_PARA4 = 0x3028
  - parameter bytes
  - read/write
- FW_STATUS = 0x3029
  - firmware running status
  - read only

Important protocol rules:
- MCU auto-clears CMD_MAIN to 0 when the command is received
- MCU auto-clears CMD_ACK to 0 when the command is completed
- if a command requires parameters, write parameter registers first and write CMD_MAIN last

======================================================================
14. AF MAIN COMMAND TABLE
======================================================================
Command codes:
- 0x03 : Trigger Auto Focus
  - no parameters
- 0x07 : Get Focus Result
  - parameters returned in CMD_PARA0..4
- 0x08 : Release Focus
  - no parameters
- 0x12 : Re-launch Zone Configuration
  - no parameters
- 0x80 : Launch default zone configuration
  - no parameters
- 0x81 : Set and launch touch mode zone configuration
  - requires parameters
- 0x8F : Enable custom mode zone configuration
  - no parameters
- 0x90 : VVF coordinate zone 0
  - requires parameters
- 0x91 : VVF coordinate zone 1
  - requires parameters
- 0x92 : VVF coordinate zone 2
  - requires parameters
- 0x93 : VVF coordinate zone 3
  - requires parameters
- 0x94 : VVF coordinate zone 4
  - requires parameters
- 0x98 : Set weight of zones
  - requires parameters
- 0x9F : Launch custom zone configuration
  - no parameters
- 0xEC : Encrypt command
  - requires parameters

======================================================================
15. AF FIRMWARE STATUS VALUES
======================================================================
FW_STATUS meanings:
- 0x7F : S_FIRWARE
  - firmware downloaded, not running
- 0x7E : S_STARTUP
  - firmware initializing
- 0x70 : S_IDLE
  - idle
  - focus released
  - lens at furthest position
- 0x10 : S_FOCUSED
  - autofocus completed
- 0x16 : S_ZONE_CONFIG
  - zone configuration stage
- 0x00..0x0F and 0x80..0x8F : S_FOCUSING
  - autofocus running

======================================================================
16. AF FIRMWARE WORKFLOW
======================================================================

16.1 Sensor Init stage
1. Initialize sensor
2. Download firmware to sensor
3. Poll FW_STATUS until it becomes S_IDLE

Pseudo-flow:
- initialize sensor
- download firmware
- repeat read FW_STATUS until FW_STATUS == 0x70

16.2 Preview stage
If sensor registers related to resolution change:
- re-launch zone configuration with main command 0x12

Pseudo-sequence:
- write CMD_ACK  = 0x01
- write CMD_MAIN = 0x12
- wait until CMD_ACK == 0

16.3 Auto Focus stage
Trigger AF:
- write CMD_ACK  = 0x01
- write CMD_MAIN = 0x03
- wait until CMD_ACK == 0

Get Focus Result:
- write CMD_ACK  = 0x01
- write CMD_MAIN = 0x07
- wait until CMD_ACK == 0
- read CMD_PARA0..CMD_PARA4 into S_Zone[0..4]

Interpretation:
- if S_Zone[i] == 0, zone i is focused
- if no zone is focused, focus failed

16.4 Release Focus
- write CMD_ACK  = 0x01
- write CMD_MAIN = 0x08
- wait until CMD_ACK == 0

17. AF ZONE CONFIGURATION
======================================================================
The autofocus firmware supports 3 zone modes:
- default zone mode
- touch zone mode
- custom zone mode

VVF coordinate system:
- Virtual View Finder size = 80 x 60
- zones are defined in VVF coordinates:
  - (X0, Y0, X1, Y1)

17.1 Zone Mode 1 - Default
- auto-launched after initialization
- fixed zone:
  - (32, 24, 48, 36)

Launch:
- write CMD_ACK  = 0x01
- write CMD_MAIN = 0x80
- wait until CMD_ACK == 0

17.2 Zone Mode 2 - Touch Mode
Definition:
- ZoneEx(X0, Y0, X0+16, Y0+12)

Constraints:
- Xc <= 72
- Yc <= 54
- other values invalid

Set and launch:
- write CMD_PARA0 = X0
- write CMD_PARA1 = Y0
- write CMD_ACK   = 0x01
- write CMD_MAIN  = 0x81
- wait until CMD_ACK == 0

17.3 Zone Mode 3 - Custom Mode
Purpose:
- fully user-defined zones at runtime

Zone constraints:
- X0, X1 <= 80
- X1 - X0 >= 8
- Y0, Y1 <= 60
- Y1 - Y0 >= 8

Special note:
- if zone 0 is used, Y1 of zone 0 must be the maximum Y1 among all zones

Zone weight constraints:
- ZoneWeight[i], i = 0..4
- 0 <= ZoneWeight[i] <= 8
- ZoneWeight[i] = 0 means zone is ignored

Custom mode procedure:
1. Enable custom mode
   - write CMD_ACK  = 0x01
   - write CMD_MAIN = 0x8F
   - wait until CMD_ACK == 0

2. Set coordinates for zone i
   - write CMD_PARA0 = X0
   - write CMD_PARA1 = Y0
   - write CMD_PARA2 = X1
   - write CMD_PARA3 = Y1
   - write CMD_ACK   = 0x01
   - write CMD_MAIN  = 0x90 + i
   - wait until CMD_ACK == 0

3. Set all zone weights
   - write CMD_PARA0 = ZoneWeight[0]
   - write CMD_PARA1 = ZoneWeight[1]
   - write CMD_PARA2 = ZoneWeight[2]
   - write CMD_PARA3 = ZoneWeight[3]
   - write CMD_PARA4 = ZoneWeight[4]
   - write CMD_ACK   = 0x01
   - write CMD_MAIN  = 0x98
   - wait until CMD_ACK == 0

4. Launch custom zone configuration
   - write CMD_ACK  = 0x01
   - write CMD_MAIN = 0x9F
   - wait until CMD_ACK == 0

18. IMPLEMENTATION NOTES FOR AN AUTOMATED AGENT
======================================================================
If an automated agent must reason about OV5640 bring-up, the following practical rules are useful:

Rule 1:
- Treat the sensor datasheet as higher priority than these app notes if any conflict exists.

Rule 2:
- First identify the intended IO voltage mode:
  - 1.8V IO mode with internal DVDD regulator
  - 2.8V IO mode with external 1.5V DVDD
- This determines whether Power Down is valid for power saving.

Rule 3:
- For 2.8V host + 1.8V OV5640 systems, level shift video signals and avoid directly driving RESETB at 2.8V.

Rule 4:
- Prefer PCLK-based sampling and matched PCLK/data routing on PCB.

Rule 5:
- During bring-up, verify in this order:
  1. supply voltages
  2. XCLK present and correct
  3. PWDN/RESET pin states
  4. SCCB bus pull-ups and address
  5. SCCB version register reads
  6. PCLK / VSYNC / HREF / data activity

Rule 6:
- For AF firmware commands:
  - write parameters first
  - set CMD_ACK to 0x01
  - write CMD_MAIN last
  - wait for CMD_ACK to return to 0 before reading result or sending next command

Rule 7:
- If preview resolution changes, re-launch zone configuration (0x12) before AF.

Rule 8:
- If AF result returns no focused zones, treat autofocus attempt as failed.
