## The question of the day

The operator asked why the PXP repack of an SXGA frame costs 62 ms and whether
ERR051248 (the "CSI cannot take RAW from MIPI" errata) really forces the 4 B/px
XYUV8888 capture.  It does not.  The errata forbids RAW and YUV422-10bit; the
4 B/px came from the VIDEO_MUX pixel reformatter.  The OV5640 has a MIPI-only
YUV420 output (`0x4300 = 0x5F`, UYY/VYY lines) and the 24-bit CSI receiver at half
width stores it as `[C,Y1,Y2,0]` per pixel pair: 2 B/px, pixel-exact at VGA and
SXGA (SXGA also needs the manual DVP PCLK divider, `0x460C = 0x22`, `0x3824 = 0x01`).
CSI writes per SXGA frame 4.9 → 2.46 MB.  Twice today "garbage" turned out to be
real data in another arrangement; colour bars + row-to-row correlation on the raw
buffer found every layout in one run each.

## The bug that mattered most

The direct-tensor path (default for months) never fed the Edge TPU.  Patching
`input_tensor(k)->data` does not reach the EvalTensor the Edge TPU op reads (TFLM
copies the pointer at allocation), so the TPU ran every frame on the untouched
arena — output identical for colour bars, a natural scene and a gradient.  Found
only because the ring made `SendInputs` print the pointers it saw.  Fixed with
`g_sentai_tpu_input_override[k]` (build 1751).  Detection quality measured on that
path before today was on stale data; production RGB detections need re-validation.

## Dead ends written down so nobody retries them

- CSICR18 MIPI bits, 0x4814, OV5640 Y8, CR20 gray mode, 8/16-bit receivers (s259).
- CSI line ring in OCRAM: the CSI DMA is SOF-gated, FB1/FB2 never alternate
  mid-frame (done rate stays 30/s with a 128-line receiver height).
- Instruction caching for the SXGA model: the loop-on-scalar-core trick
  (tinycoral `INSTRUCTIONS_ONCE.md`) needs the program ≤ 16 384 words; VGA
  detectors fit, the 297 KB SXGA program does not.
- Legacy 4 B/px capture at a true SXGA 30 fps: 147 MB/s of CSI writes starve the
  SDRAM, the full pipeline hangs the board (REPL silent, no crash log).

## Lockstep

With the sensor at a true 15 fps the SXGA pipeline processes every frame (1805 of
1806 in 120 s, invoke 60 ms inside a 66.7 ms period).  At 30 fps it processes 54 %
with a non-deterministic slip, which would desynchronise two-camera alternation.
Measure it with the CSI frame counter and the InferTask ok count read in one REPL
statement in steady state; a start..stop window under-counts by ~8 %.
